# Qbook v2 — спека переписывания

Ветка `rewrite`. База — `main` на `6ff0abd` (v0.1.0: читалка + перевод работают,
но рендерит плоский текст, старт медленный, перевод непонятно как поднимать).

## Цели

1. **Полноценный rich-text из EPUB** — жирный/курсив/подчёркнутый/зачёркнутый,
   над/подстрочный, ссылки, блоки всех видов и картинки *в потоке текста*.
   Мастхев проекта.
2. **Скорость** — открытие, скролл, переключение языка/ширины без заметных
   пауз на больших книгах.
3. **Перевод стал явным** — `qbook translate` работает из коробки, с прогрессом,
   доктором окружения и resume; запускается и из читалки.
4. **GUI-эстетика btop** — сохранить и усилить: рамки, метрики в заголовках,
   градиенты, бар, панель прогресса перевода, угол-превью картинок.
5. **Упростить** — Markdown-режим выпилен совсем (`.md` не открывается).

## Что сохраняется из v0.1.0

- Ядро позиционирования: `Anchor { block, frac }` в координатах базового
  документа; смена языка не двигает позицию.
- Выравнивание переводов (быстрый путь + banded NW), кэш в SQLite.
- SQLite (XDG data dir), миграции через `PRAGMA user_version` — не ниже, чем v3;
  полка, прогресс, закладки, сайдкары `book.<lang>.epub`.
- Оболочка btop: три колонки, клавиатурный бар, шапка, тосты, темы
  (btop/mono/light + `config.toml`), справка `h`.

## Что выпиливается

- Парсер Markdown и весь md-флоу: `.md` → внятная ошибка «не поддерживается».
  TXT остаётся, но без md-разбора: любые `#`/`>` — обычный текст; единственная
  мягкая логика — пустая строка = граница абзаца.
- Markdown-маркеры `*`/`_` внутри блоков и хак `style_inline` в рендере —
  вместо них настоящие `Span`-стили из парсера.
- Eager-загрузка всех вариантов на старте (сайдкары парсятся при первом `t`).
- Зависимость `scraper` (+html5ever) — EPUB-разбор переезжает на quick-xml.

## Модель данных

```rust
struct InlineStyle {
    bold: bool,
    italic: bool,
    underline: bool,
    strike: bool,
    sup: bool,
    sub: bool,
    /// Индекс в Document.hrefs; None — обычный текст.
    link: Option<usize>,
}

struct Span {
    text: String, // без \n внутри
    style: InlineStyle,
}

enum BlockKind {
    Paragraph,
    Heading(u8),
    Quote,
    ListItem,
    Code,
    Verse,
    Rule,
    Image,
}

struct Block {
    kind: BlockKind,
    spans: Vec<Span>,
    /// Отступ слева в колонках: вложенные списки, цитаты, стихи.
    indent: u8,
    /// Префикс строки («•», «1.», «›») — рендерится только на первой строке блока.
    marker: Option<String>,
    image: Option<ImageRef>,
}

struct ImageRef {
    /// Путь ресурса внутри zip (например OEBPS/img/x.png), уже нормализованный.
    resource: String,
    alt: String,
}

struct Document {
    lang: String,
    title: String,
    blocks: Vec<Block>,
    /// manifest-href'ы ссылок; `InlineStyle.link` — индекс сюда.
    hrefs: Vec<String>,
    toc: Vec<TocItem>,
    /// Префиксные суммы символов по блокам (как в v0.1.0).
    prefix: Vec<usize>,
}
```

Инварианты (проверяются `Document::validate`, как в v0.1.0):

- непустой текстовый `kind` имеет непустые спаны; `Rule`/`Blank` — пустые;
- `char_len` блока = сумме длин текстов его спанов, префиксные суммы сходятся;
- индексы — в **символах**, не в байтах;
- `Image`-блок всегда с `Some(image)`; остальные — `None`;
- TOC-индексы и link-индексы внутри документа.

`Anchor`/`TocItem` — без изменений. Схема выравнивания, прогресс, закладки —
без изменений.

## Парсер EPUB v2 (`parse/epub.rs`)

Источник правды — spine-порядок. Схема как в v1 (`container.xml → OPF →
manifest/spine → XHTML`), но разбор файла — потоковый на `quick-xml`:

1. **Контейнер/OPF** — как раньше: `dc:title`, `dc:language`, manifest (href
   ресурсов запоминаются), spine.
2. **XHTML по spine, параллельно**: файлы разбираются в thread-pool
   (`std::thread::scope`, N = `available_parallelism`), результат собирается
   в spine-порядке. Ошибка одного файла не валит книгу: файл пропускается
   (в debug-режиме — предупреждение в stderr).
3. **Разметка → стили**:
   - `b/strong` → bold; `i/em/dfn/cite` → italic; `u/ins` → underline;
     `s/del/strike` → strike; `sup`/`sub` → sup/sub;
   - `a[href]` → `link` (href'ы копятся в `Document.hrefs`);
   - inline-контент склеивается в потоке блока; блочные теги
     (p/h1–h6/li/blockquote/pre/div/td/dt/dd/figcaption) открывают/закрывают
     блоки; вложенные списки увеличивают `indent`;
   - `img`/`image`(svg)/`figure>img` → `BlockKind::Image` с `resource`
     (нормализованный href из manifest) и `alt`; `figure` без картинки —
     обычный блок;
   - игнорируются: `head`, `style`, `script`, `title`, `template`, `svg`-графика
     (кроме `image`).
4. `pre` → Code, `td` со стихами → Verse — kind'ы как в v1, чтобы не разъезжалось
   выравнивание и заметки.

Приёмка: тесты на фикстуре `tests/fixtures/sample-epub-v2` (собирается в тесте
через `zip::ZipWriter`, без сторонних файлов):

- spine-порядок сохранён;
- вложенный `em` внутри `strong` даёт оба флага;
- ссылка даёт span со `link` и попадает в `hrefs`;
- `<img>` → Image-блок с корректным `resource`;
- сломанный XML одного spine-файла не рушит книгу;
- `.md`-путь в `parse::load` даёт ошибку с человекочитаемым пояснением.

## Layout v2 (`model/layout.rs`)

Ключевое изменение — **окновый layout** вместо полной раскладки документа:

- `Layout` больше не строит `LineInfo` для всех строк документа. Хранится:
  - `line_counts[block] -> usize` — сколько строк (включая blank-отступ)
    занимает блок при заданной ширине;
  - LRU-кэш переноса отдельного блока при данной ширине (капа ~64 блока);
  - префиксные `line_offsets[block] -> usize` — `anchor↔scroll` бинарным
    поиском за O(log n).
- `layout_window(center_block)` создаёт и кэширует `LineInfo` только для
  видимой области (центральный блок ± пара десятков блоков).
- Перенос внутри блока — по спанам: прежний алгоритм ширины (графемы,
  дефис/slash/CJK/эмодзи), но `LineInfo` дополнительно знает границы спанов;
  рендер собирает ratatui-Spans без перепарсинга.
- API для остального кода сохраняется: `line(idx)`, `block_range(block)`,
  `scroll_to_anchor`, `anchor_to_scroll`.

Метрики (бенч в `tests/perf.rs`):

- открытие книги 10k блоков: парсинг + первый layout ≤ 300 мс;
- кадр скролла: ≤ 5 мс;
- рефлоу (смена ширины/языка): ≤ 50 мс.

## Хранилище (`store`)

SQLite остаётся. Миграция `PRAGMA user_version` 3 → 4. Новая таблица:

```sql
-- Журнал перевода для resume (см. раздел Translate).
CREATE TABLE translate_jobs (
    id INTEGER PRIMARY KEY,
    src_hash TEXT, dst_path TEXT,
    from_lang TEXT, to_lang TEXT, engine TEXT, base_url TEXT,
    created_at INTEGER
);
CREATE TABLE translate_units (
    job_id INTEGER REFERENCES translate_jobs(id) ON DELETE CASCADE,
    unit TEXT,        -- «ch3.xhtml#u42»
    state INTEGER,    -- 0=pending, 1=done, 2=failed
    PRIMARY KEY (job_id, unit)
);
```

Остальное (books/variants/progress/bookmarks/alignments) — без изменений,
схема v3 продолжается: шаг миграции 4 ничего не трогает в старых таблицах.

## TUI v2 (`ui/`)

Оболочка btop остаётся концептуально: шапка книги, левая «Главы», центр —
рамка текста с метриками и градиент-прогрессом, правая «Заметки»·«Команды»,
слот, клавиатурный бар, угол `S полка · Q выход`, тосты, справка, полка.

Изменения:

- рендер текста идёт напрямую из `Span`-модели: `InlineStyle → ratatui::Style`
  конвертируется в одном месте с учётом темы;
- видимая область всегда собирается из **окнового layout** — нет генерации
  `Vec<Line>` на весь документ;
- Image-блок рендерится в кадре по месту (см. «Картинки»);
- заметки/поиск/выделение поверх спанов: подсветка применяется к строкам
  `LineInfo` как фон/модификатор;
- хоткеи и команды v0.1.0 сохраняются, обновляется только HELP и README.

## Картинки

Двухуровневая схема, включается конфигом (`[defaults] images = "auto"`;
`auto | half | kitty | sixel | off`):

- **Tier 1 (дефолт, универсально)**: полублочный даунскейл средствами
  терминальных ячеек — пиксельная матрица кодируется парами `▀` с fg/bg-цветом.
  Рендерится прямо в потоке текста: Image-блок занимает `ceil(h)` строк,
  перенос не переживает (изображение фиксированной ширины в ячейках).
- **Tier 2**: kitty graphics protocol (escape-последовательности с base64 PNG)
  — по детекту (`KITTY_WINDOW_ID`, `TERM=xterm-kitty`, `WEZTERM_*`). Sixel —
  опционально, после базового релиза.
- **Декодер**: `image` crate (png/jpeg/gif/webp), ресайз до ячеек, LRU-кэш
  декодированных картинок (капа ~32 МБ).
- **Угол-превью**: при курсоре на Image-блок — панель с крупной версией
  (kitty — полный формат, иначе полублок в большем окне).

## Translate

Фича переводится из optional в дефолтную сборку (ядро больше не притворяется,
что не умеет; `ureq` остаётся, но включён всегда). CLI:

```
qbook translate <книга.epub> <to> [--from LANG] [--engine libretranslate|ollama]
               [--base-url URL] [--jobs N] [--batch N] [--out путь]
               [--check]           # doctor: пинг сервера, языки, модель
               [--dry-run]         # сколько юнитов будет переведено
               [--no-resume]
```

- **Прогресс**: stderr-бар «документ 3/17 · блок 148/602 · ETA 2 мин».
- **Журнал + resume**: каждый переведённый юнит пишется в `translate_units`;
  повторный запуск с той же комбинацией (src_hash, from, to, engine, base_url)
  продолжает с места остановки. `--no-resume` — начать заново.
- **Доктор `--check`**: пинг LibreTranslate (`/languages`), список языков,
  готовые команды поднятия: `pip install libretranslate` →
  `libretranslate --load-only en,ru`; для ollama — `ollama list` и подсказка
  по модели.
- **Движки**:
  - `LibreTranslate` (как в v0.1.0, шаблоны с токенами `[[n]]`/`[[/n]]`);
  - `Ollama` — OpenAI-совместимый `/v1/chat/completions` локального сервера
    (Ollama/LM Studio); промпт передаёт блок целиком без токенов, батчами.
- **Внутри читалки**: `:translate ru` открывает панель «Перевод: 42% ▓▓▓░»;
  задача крутится в отдельном потоке, UI не блокируется; по готовности тост
  «сайдкар готов», варианты rescan-ятся — `t` сразу видит новый язык без
  перезапуска.

## Клавиши / команды (дельта к v0.1.0)

Без изменений: навигация, `t`, поиск, заметки, полка, темы.

Новое:

- `i` — угол-превью картинки (когда под курсором Image-блок);
- `:translate <lang>` — перевод книги в фоновой задаче;
- `.md` не открывается: тост/CLI-ошибка «markdown не поддерживается».
